# v1.10.0 — one name per device

A device now has exactly **one** name with exactly one home. The two-name
state the panel used to explain — a policy-row label *and* an identity-layer
alias on the same host — is migrated out of existence, and the explanatory
UI leaves with it. Underneath: the release process itself gained the push-time
gates whose absence made v1.9.0's release day harder than it needed to be.

## What's new

- **One name per device.** A single host (`/32`) is named by its **alias** —
  the identity-layer name that survives the device's policy being removed,
  where your own edit outranks every importer. A range keeps its policy-row
  `name`, the only name an address without a single host can carry. The
  "Policy label (superseded by the alias)" row and its **Retire label**
  button are gone, because the state they explained can no longer exist.
- **Upgrading changes no name you see.** The startup migration moves a label
  that had no alias into the identity layer as your own edit, and retires a
  label an alias had already displaced into the audit trail
  (`rename 'old' -> ''`) — recoverable, never silently destroyed. The name
  each device displays is **identical before and after**, by construction
  and by test.
- **Release safety, on every push** (developer-facing): CI now builds both
  curated bundles with the identity leak-gate live, and builds the panel
  image, on every push to master — the two failure classes that previously
  could only surface on release day now fail the push that introduces them.

## Upgrading from v1.9.0

**Deploy the new panel image and recreate the panel container** — that is
the whole upgrade for the running stack. `docker-compose.yml` is unchanged
and no new `.env` key is required. The panel migrates its own database
forward on startup; the migration is additive against a populated v1.9.0
store, moves data rather than destroying it, and records every moved or
retired label in the audit trail (requester `migration`).

Worth knowing:

- The UI ships **inside the panel image**: an image that has not been
  republished keeps serving the old panel. The visible difference in this
  release is small on purpose — check the Devices tab: a v1.10.0 panel never
  shows a "Policy label (superseded by the alias)" row.
- Renaming is unchanged in daily use: one control, writing whichever layer
  the address can carry. Vendor alias syncs (`gateway.sh alias --sync`) keep
  working exactly as before — the migration never claims an importer's row,
  so the next sync still owns what it owned.
