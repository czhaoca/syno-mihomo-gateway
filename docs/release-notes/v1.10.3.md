# v1.10.3 — stats windows that include today (DRAFT until tagged)

A one-fix patch release. The panel's 7-day and 30-day stats views were
missing the newest 48 hours, and the "daily" view was missing the last 90
days. Totals in those views now go up to the present.

## What's fixed

- **Every stats range covers its whole window.** Collected traffic moves
  from minute rows to hour rows to day rows as it ages, and each of those
  tiers holds a different stretch of time. The browser used to pick one
  tier per range and read only that table, so a 7-day view never saw the
  last two days and "daily" never saw the last three months. The panel now
  asks the server for the range by name (`range=48h|7d|30d|daily`), and the
  server reads the range's own tier plus every finer tier that still holds
  newer rows. Days that have not been rolled up yet are keyed under your
  current timezone and day start, the stamp they will carry once rolled, so
  a window that spans a changed day boundary still says so.

## What changes for you

- **The 7d, 30d and daily numbers get bigger.** They were too small; they
  now include the most recent traffic. This is the intended correction, and
  the owner acknowledged it as a fix rather than a contract change: the
  same view now answers with more rows.
- **The API is additive.** `range=` is a new optional parameter on
  `/v1/stats/devices`, `/v1/stats/chains` and `/v1/stats/timeline`. A
  request that sends only `tier` (and optionally `since`/`until`) still
  reads that single tier table and returns exactly what it did before.
  `range` together with `since` or `until` (even an empty one) is refused
  with 422, because the range already defines the window. An explicit
  `tier` beside `range` sets the resolution only; a tier finer than the
  window reaches back only as far as that tier holds.
- **Lowered retention still shortens a window.** Coarser rows are never
  split back into finer ones, so with `PANEL_STATS_MINUTE_HOURS` below 48 or
  `PANEL_STATS_HOUR_DAYS` below 30 the 48-hour or 30-day view ends at that
  retention, exactly as before. The shipped defaults are unaffected.
- **The 48-hour attribution note covers one more hour.** The coverage
  report's window now starts on a whole hour, matching how that table is
  keyed, so the partly elapsed first hour of a 48-hour window is counted
  instead of dropped.
- **Only the daily view reads your timezone.** A range read looks up the
  configured timezone (kept in the policy store) only when it keys traffic
  by local day, so the 48h, 7d and 30d views never wait behind a
  device-policy change that is still being applied.

## Upgrading from v1.10.2

Deploy the new panel image and recreate the panel container. Nothing else
changes: `docker-compose.yml`, the `.env` knobs and the stats database are
untouched, and there is no migration. The UI ships inside the panel image,
so an image that has not been republished keeps serving the old views.

## Validation notes

`validate_release.sh` phase **A6 remains a required gate**. The panel's unit
suite gains two property tests for the stats tiers, run across several
timezones (including a half-hour offset and DST transitions) and small
retention settings: a window read cannot tell rolled rows from unrolled
ones (identical per device, per bucket and per framing, with the total equal
to the bytes inside the window), and a rollup never loses or duplicates a
byte at any point in time.
