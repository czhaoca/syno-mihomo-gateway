# v1.9.0 — the panel you can actually read

The panel's web UI is rebuilt in React, opens on **Stats** instead of the
policy editor, gains a real **settings page**, and shows an audit log that
fits the screen it is on. Underneath: device names that survive losing their
policy, a stats day keyed to *your* local midnight, and an honest measurement
of how much traffic can be attributed to an app at all.

## What's new

- **Stats is the landing tab.** The window it opens on is a *setting*
  (`48h | 7d | 30d | daily`, default 7 days), not a constant baked into the
  bundle — so changing it does not mean shipping a new panel.
- **Settings page**: timezone, the hour a stats day starts, the landing
  range, and device aliases. Each value says whether it is **yours or
  inherited**, because presenting an inherited default as a stored choice is
  the same class of lie as a badge that claims an apply reached mihomo when
  it did not.
- **The audit log fits.** One entry per card below 760px, a real table above
  it. Timestamps, addresses and requester IPs no longer shatter mid-token —
  `2026-07-26T14:03:11Z` used to render as `2026-07-2 / 6T14:03:1 / 1Z`. It
  pages through the server's existing `offset` instead of dumping 200 rows,
  and an older page says it is paused rather than reshuffling as you read.
- **Device aliases** (`gateway.sh alias --list | --sync --from unifi|file`):
  a name lives in its own layer, so it **survives the device's policy being
  removed**, and a name you typed outranks every importer. The panel never
  holds a vendor credential — the adapter runs on the host and the secret
  rides stdin, never argv and never the container environment.
- **The stats day is local.** Day-tier rollups key to your timezone and to an
  hour you choose (default 03:00, so a late-night session belongs to the day
  it began). Rows record the framing that produced them, so a window whose
  day *definition* changed part-way says so instead of quietly summing two
  different things.
- **Attribution, measured before it is used.** `/v1/stats/coverage` reports
  what share of traffic could be attributed to an app at all, together with
  the window it was measured over — the number comes first, because blocking
  on bad attribution takes out the wrong app on a gateway carrying all LAN
  traffic.
- **Warnings cannot be suppressed.** The apply-drift warning left `alert()`,
  which a browser can switch off for a page; it renders in-page now, stays
  put when you scroll, and stacks rather than overwriting an unread one.

## Upgrading from v1.8.0

**Deploy the new panel image and recreate the panel container** — that is the
whole upgrade for the running stack. `docker-compose.yml` is unchanged, and
no new `.env` key is required (the `UNIFI_*` block ships commented out and is
only needed for `alias --sync --from unifi`). The panel migrates its own
database forward on startup; the migrations are additive and non-destructive
against a populated v1.8.0 store.

Two things worth knowing:

- The UI now **ships inside the panel image**. An image that has not been
  republished keeps serving the old panel, and the release gate's A6 marker
  is present in both, so it cannot tell them apart. A deployed v1.9.0 panel
  serves `/ui/assets/` and a `<div id="root">`; the old one serves `app.js`.
- Existing day rows keep the `00:00` UTC framing they were written with. The
  new boundary applies to rows rolled from here on, and the framing note in
  the stats view is what makes a mixed window visible rather than misleading.

## Validation notes

`validate_release.sh` phase **A6 remains a REQUIRED gate**. Beyond the
existing suites this release adds a browser gate: 29 Playwright specs drive
the built panel in real Chromium (zero external requests asserted at runtime,
badge honesty in both directions, no horizontal overflow at 1280px and 390px,
the band confirm, the naming rule). 59 mutants against the page and the
gates were each confirmed to turn something red.
