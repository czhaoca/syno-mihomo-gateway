# v1.14.0 — Gateway Insights: live throughput, node delay and quota (DRAFT until tagged)

The last slice of Gateway Insights. The overview gains three widgets the
panel reads from mihomo itself: a live throughput tile, the delay history
of each policy group's selected node, and each provider's subscription
quota. Node operations (switching, testing) stay on MetaCubexD.

## One release for five versions

v1.14.0 is the first release published after v1.10.2. It also carries four
versions that were never published on their own. Their notes describe each
change in full:
- [v1.10.3](v1.10.3.md): the stats windows include today;
- [v1.11.0](v1.11.0.md): the Gateway Insights groundwork - a faster
  collector, the star schema, and the collector's telemetry with the A6c
  gate;
- [v1.12.0](v1.12.0.md): categories, the breakdown and overview API with
  CSV, and an opt-in Prometheus `/metrics`;
- [v1.13.0](v1.13.0.md): the Insights screens, with drilldowns, the chart
  kit and dark mode.

The upgrade and the validation below cover all five.

## What's new

- **Live throughput** in the overview. The tile is off until you tick it,
  and the choice is kept by that browser only. While on, it shows the
  gateway's upload and download per second, now and over the last minute.
  - **Nothing from it is stored.** The tile says so. The history stays in
    the timeline.
  - **Never a frozen number.** After 3 s with no new figure, the rates give
    way to "No new figures for Ns".
  - **One stream per tab, and only while you look.** Hiding the tab closes
    the stream; showing it opens a new one. The panel reads mihomo's
    `/traffic` only while at least one browser holds a stream, and one
    upstream serves every viewer, up to 16.
- **Node delay** in the overview: for each policy group, the selected node,
  its newest test and the range's tests as a strip.
  - The delays are the tests mihomo itself runs, read every 300 s. The panel
    never probes a node.
  - A failed test is "no answer", hatched, never 0 ms. A stretch with no
    test is blank.
  - 24h and 48h show every test; longer ranges show one value per hour and
    node, with how many tests failed.
  - The history is kept for `PANEL_NODE_DELAY_DAYS` (14 days by default,
    7 to 30). A range longer than that says where it really starts.
- **Subscription quota** in the overview: each provider's used traffic
  against its total, its expiry and when the provider last reported,
  sampled hourly. The text gives the true share, so an overrun reads as
  one, and a past expiry says "Expired". mihomo writes 0 for a number the
  provider did not send, so a 0 total or expiry is shown as unknown, never
  as a limit. Only those numbers are kept: never the provider's URL or its
  nodes.
- **Honest widget states.** Each widget says when it is stale (with the time
  of its newest data), when it cannot be read, and when nothing is stored
  yet, in its own words, never in traffic's.

## What changes for you

- **API (additive):**
  - `GET /v1/stats/live`, a Server-Sent Events stream;
  - `GET /v1/stats/node-delay?range=`;
  - `GET /v1/stats/quota`;
  - the purge table list gains `stats_node_delay`;
  - `/health` gains `live_viewers`.

  The event schema is in `docs/panel-api.md`.
- **A new optional knob:** `PANEL_NODE_DELAY_DAYS`, in `.env.example`. Leave
  it unset for 14 days.
- **The overview reads two more endpoints**, on their own cadence: node
  delay and quota, every 300 s (every 10 s until a first answer, and after a
  failed one). They never read while the tab is hidden, not even on open,
  and never beside a read in flight. A device,
  category or hostname view reads neither.
- **A faster stop.** The panel image now stops uvicorn after a 5 s graceful
  shutdown. An open stream used to hold `docker stop`, and an automatic
  rollback, until it was killed.
- **The bare purge** (`POST /v1/stats/purge` with no body) also clears the
  stored quota, and the overview's widgets re-read at once after it. A
  device purge leaves the node delay alone, because it belongs to no
  device.

## Downgrading, or an automatic rollback

Stats schema **v8** only creates the `stats_node_delay` table and its index.
It drops and rewrites nothing, so an older panel opens the database as it
is. What an older image cannot do:
- it cannot prune, cap or purge `stats_node_delay`;
- it cannot touch the stored quota.

Both wait, unchanged, until a v1.14 panel returns and manages them again.
The table is small: one row per group every 5 minutes. The UI ships inside
the panel image, so an older image serves its own UI, with no widgets.

## Upgrading from v1.10.2

Install the new bundle and deploy its panel image: the compose file gains
two optional passthroughs, `PANEL_METRICS` (v1.12) and
`PANEL_NODE_DELAY_DAYS`. No `.env` change is required. Every new knob is
optional:
- `PANEL_STATS_POLL_S` now defaults to 2 s (v1.11);
- the doctor's `PANEL_MIHOMO_MEM_WARN_MB` (v1.11);
- `PANEL_METRICS` (v1.12);
- `PANEL_NODE_DELAY_DAYS`.

On first start the stats database migrates through schema v3 → v8, in
order. Each step creates tables, columns or indexes and drops nothing, and
the minute rows move to the new minute table with their hours completed
(v1.11). An image that has not been republished keeps serving the old
panel, because the UI ships inside it.

## Validation notes

`validate_release.sh` phases **A6 and A6c are required gates**, on a panel
image built from the tag. This one run validates v1.10.3 to v1.14.0. Record
the items each version's notes ask for:
- **v1.11 (#96 REQ-ADD):**
  - `collector_poll_ms`, quiet and busy;
  - the `stats_gap` rows created during the run, each matched to the
    redeploy or A6's mihomo restart;
  - `stats_minute` empty after the start.

  If `collector_poll_ms` exceeds 500 ms or a gap appears with no outage
  behind it, the poll default goes back to 5 s before this release is
  published.
- **v1.12:**
  - `GET /v1/stats/coverage` has `dictionary.version` set and
    `dictionary.error` null;
  - the breakdown and overview reads answer 200;
  - `GET /metrics` answers 404 with `PANEL_METRICS` unset.
- **v1.13:**
  - `GET /v1/stats/overview?range=24h` answers with `totals.tier`
    `minute`;
  - in a LAN browser, the panel opens on Insights, drills from a device to
    a category, and keeps the view across a reload;
  - the scheme picker switches light and dark.

For v1.14 itself:
- **The running mihomo streams `/traffic` without a WebSocket upgrade**
  (#102 DEC-A, owed since that slice). From a LAN host,
  `curl -sN http://<PANEL_IP>:8090/v1/stats/live` must print `retry: 5000`
  and then a `data:` line about once a second, and `/health` must report
  `live_viewers` 1 while it runs and 0 once it stops.
- In a LAN browser, the live tile is off on first visit. Ticked, it shows
  rates and a sparkline, and survives a reload. A hidden tab drops
  `live_viewers` back to 0 within the 15 s heartbeat.
- After at least 300 s, `GET /v1/stats/node-delay?range=24h` lists the
  policy groups. Each group's newest delay matches MetaCubexD's for its
  selected node.
- After the first hourly sample, `GET /v1/stats/quota` has `state` `ok` (or
  `none` with no subscription). Each provider's used, total and expiry match
  MetaCubexD's provider card.
- `docker stop` of the panel, with a stream open, returns within about 5 s.
