# v1.10.2 — quieter boots, safer validation (DRAFT until tagged)

A patch release of five hygiene fixes found while proving v1.10.1 on real
hardware. A healthy gateway behaves exactly as before; what changes is the
noise a boot leaves behind, two loops that could misjudge or spin on a bad
setting, and how the release validator picks and cleans up after itself.

## What's fixed

- **A healthy boot no longer logs errors.** While Container Manager was
  still starting, the Boot-up task wrote an ERROR line on every poll
  (`docker binary not found`, `Docker daemon is unavailable; start Container
  Manager and run this task as root`) plus two `docker=` INFO lines — on a
  boot that was fine. The wait now polls quietly, keeps its one `waiting
  for …` WARN per interval, names the cause once only if it times out, and
  reports the Docker/Compose it found once, after readiness (which also
  settles the compose flavor with the CLI fully installed).
- **Boot-time settings are validated before anything is touched.**
  `DOCKER_READY_TIMEOUT`, `DOCKER_READY_INTERVAL`, `HEALTH_INTERVAL`,
  `BOOT_HEALTH_RETRIES` and `TUN_SETTLE_GRACE` must be integers in range; a
  bad value stops the Boot-up task with exit `2`-style loudness (exit `3`,
  naming the knob) instead of misreading the dataplane or spinning on a
  zero interval. The two v1.10.1 knobs now appear, commented, in
  `.env.example` and the CONFIGURE guide.
- **`doctor.sh` says where the JSON is.** An unknown flag such as `--json`
  still exits `3`, but the usage line now points at
  `sh scripts/gateway.sh doctor --json`, so it can no longer be mistaken for
  a broken check.
- **Release validator (maintainers):** the staged bundle is picked by
  version, not by string order (`1.9.0` no longer beats `1.10.2`), only
  enduser bundles qualify, and extras are listed in the WARN block; an
  interrupted run restores the parked caches and the original `.env`, and
  its transcript survives the terminal's Ctrl-C.

## Upgrading from v1.10.1

**Refresh the release tree** — that is the whole upgrade. No container
image changed, `docker-compose.yml` is unchanged, and no new `.env` key is
required. One deliberate behaviour change: a malformed value for any of the
five boot-time knobs above now stops the Boot-up task (exit `3`, DSM error
mail) where v1.10.1 ran on regardless. Defaults are unchanged, so an
untouched `.env` is unaffected.

## Validation

Validated on the production NAS before this release was published: the full
on-device gate — deploy, split-horizon rendering, cold start with parked
caches and black-holed tunnel resolvers, fail-closed long-tail DNS,
LAN-client routing probes, the REQUIRED A6 panel gate, and the
DNS_GEOIP_NO_RESOLVE round-trip — the new boot helper run on the live stack,
an interrupted validator run (Ctrl-C during the cold-start block) leaving no
parked cache behind, and a real reboot with the boot log checked for silence.
Both CI surfaces (Woodpecker's 15 steps and the `panel-image` build check)
were green on the release commit before it was tagged. The panel image is
unchanged since v1.10.0 (`app/` is byte-identical), so no image was
republished.

The `-linux` assets remain **experimental** (no real-hardware validation).
