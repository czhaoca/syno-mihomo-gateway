# v1.14.1 — node delay on real mihomo (DRAFT until tagged)

v1.14.1 is the first release published after v1.10.2. It ships everything
in [v1.14.0](v1.14.0.md), which in turn carries v1.10.3, v1.11.0, v1.12.0
and v1.13.0, plus one fix. v1.14.0 was tagged but never published,
because its NAS validation found the bug fixed here. The upgrade from
v1.10.2 and the validation list are in [v1.14.0's notes](v1.14.0.md); they
apply unchanged.

## Fixed

- **Node delay stayed empty on a real gateway.** The panel read each node's
  test history from `GET /proxies/<node>`, which is the wrong place on real
  mihomo in two ways:
  - **A URLTest or Fallback group selects a provider's node.** mihomo answers
    `/proxies/<node>` for such a node with 404; its history lives in
    `/providers/proxies`.
  - **A Selector usually selects another group.** That group's own history
    is empty.

  The v1.14.0 run on the NAS stored nothing for any of its 11 groups. The
  sampler now reads every provider node's history in one
  `/providers/proxies` read, and follows a selection through groups to the
  node traffic actually leaves by: a Selector on "Auto" charts the node
  "Auto" picked. Against the same gateway, a sample now stores 10 of 11
  groups; the eleventh is parked on DIRECT, which has no node to chart. A
  node that `/proxies` does not know now counts as having no history, not
  as a failed read.

## Downgrading, or an automatic rollback

As for v1.14.0: the stats schema is unchanged (v8), so an older panel opens
the database as it is.

## Validation notes

`validate_release.sh` phases **A6 and A6c are required gates**, on a panel
image built from the tag. The v1.14.0 checks apply. The node delay check
must now list the groups, with each group's newest delay read from its
provider node.
